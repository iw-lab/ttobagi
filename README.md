# 또박이 — 초등 받아쓰기 (ttobagi)

교실과 집에서 그대로 쓰는 **초등 받아쓰기 앱**. 서버도, 로그인도, 요금도 없습니다.
브라우저만 있으면 **휴대폰 · 웨일북 · PC · 전자칠판** 어디서든 같은 주소로 열립니다.

## 왜 이렇게 만들었나

받아쓰기는 학교에서 이미 잘 굴러가는 활동입니다. 앱이 새로 할 일은 **읽어 주기 · 채점 · 오답 되풀이** 세 가지뿐이고,
그걸 위해 아이 이름과 점수를 남의 서버에 올릴 이유는 없습니다. 그래서 이 앱은 **아무것도 전송하지 않습니다.**
급수표도 기록도 브라우저 안(localStorage · IndexedDB)에만 있고, 나눠 줄 때는 **주소 자체에 담아** 보냅니다.

- 운영비 0원 — 서버·DB·유료 API 없음, GitHub Pages 정적 호스팅
- 개인정보 유출 경로 0개 — 네트워크로 나가는 학생 데이터가 없음
- 설치 없이 오프라인 — PWA 서비스워커, 와이파이가 끊겨도 시험 진행

## 써 보기

바로 열기 → **https://ttobagi.pages.dev/**

학교 망에서 `github.io` 가 막히는 경우가 있어 **Cloudflare Pages 를 정본 주소로** 씁니다.
GitHub Pages(https://iw-lab.github.io/ttobagi/)는 같은 내용의 예비 주소입니다.
둘 다 무료이고, 어느 쪽으로 열어도 기능은 같습니다 — 다만 저장한 급수표는 주소(출처)별로
따로 보관되므로, **한 교실에서는 한 주소로 통일**해 쓰는 편이 낫습니다.

처음 화면에서 `급수표 만들기` → 문항 붙여넣기 → `저장하고 연습`.
교실에서는 저장 후 `칠판 모드`, 학생에게는 QR을 보여 주면 됩니다.

## 개발

```bash
npm install
npm run dev        # http://localhost:5173/ttobagi/
npm test           # vitest — 채점 엔진(국어·영어)·급수표·공유·저장소
npm run typecheck  # tsc --noEmit
npm run build      # dist/
npm run qa         # 빌드 후 실제 브라우저(퍼피티어) 31개 점검 + 스크린샷
```

`npm run qa` 는 휴대폰(390) · 웨일북(1366) · 전자칠판(1920) 세 화면에서 실제로 눌러 보고
`qa-report.json` 과 `qa-shots/*.png` 를 남깁니다. 콘솔 에러가 하나라도 나면 실패로 끝납니다.

```bash
npm run qa:sound   # 소리가 «실제로» 나는지 검사 (창을 띄워 진짜 클릭으로 누른다)
npm run audio      # 국어 급수표 문항을 Supertonic 으로 읽어 public/audio 에 굽는다
node scripts/en/build-audio.mjs --jobs 8   # 영어는 piper 로 (scripts/en/RUNBOOK.md 참고)
npm run deploy     # 루트 경로로 빌드해서 Cloudflare Pages 에 올린다 (wrangler 로그인 필요)
```

`npm run qa` 는 화면만 봅니다. **소리는 화면 검사로 절대 잡히지 않아서** `qa:sound` 를 따로 둡니다 —
브라우저 음성은 조용히 실패하는 방법이 여러 가지입니다(사용자 조작과 이어지지 않으면 `not-allowed`,
큐가 한 번 엉키면 `speaking=true` 인 채로 영원히 멈춤). 그래서 내장 급수표는 아예 음성 합성에 기대지
않고 **미리 구운 파일**을 재생합니다.

배포된 주소를 검사하려면 `QA_BASE=https://ttobagi.pages.dev/ npm run qa`.
GitHub Pages 쪽은 main 에 push 하면 워크플로가 알아서 올립니다.

## 구조

```
src/engine/   hangul.ts  자모 분해·결합, 혼동쌍 표
              english.ts 영어 철자 판정 — 묵음·겹자음·어미·동음이의·ie/ei
              grade.ts   글자 정렬(가중 Levenshtein) + 거리 + 오류 유형 판정
                         언어별로 다른 것은 부호 범위·공백/대소문자·닮음·거리 단위 넷뿐
              store.ts   localStorage 저장소 (용량 초과 시 오래된 기록부터 정리)
              speech.ts  녹음 재생 → 브라우저 TTS → 없음, 순서가 곧 정책
              share.ts   deflate-raw → base64url → 주소 해시, QR
src/ui/       writing.ts 손글씨 패드 (Pointer Events, 조건부 손바닥 무시)
              blocks.ts  글자 블록 입력 (교육적으로 의미 있는 오답 보기 — 국어는 자모, 영어는 알파벳)
src/views/    home lists listEdit run result report board print open
```

채점 판정은 `correct` / `partial` / `wrong` 세 가지지만 **점수에 들어가는 건 `correct` 뿐입니다**
(`partial` 은 "아깝다"를 보여 주기 위한 표시 전용). 이 규칙은 `isCorrect()` 한 곳에만 있습니다.

## 한계 — 알고 만든 것

- **손글씨 자동 인식은 없습니다.** 유료 API 없이 초등 저학년 글씨를 인식하면 오답을 정답이라 우기게 됩니다. 사람이 ○/× 를 누릅니다.
- **리모컨은 같은 브라우저 안에서만** 동작합니다(BroadcastChannel). 서버가 없으니 다른 기기끼리는 이어지지 않습니다.
- **기기를 바꾸면 기록이 따라오지 않습니다.** 대신 결과 링크/QR로 넘깁니다.
- **영어는 「소리를 듣고 철자를 쓰는」 연습입니다.** 뜻·문법을 가르치지 않습니다.
  낱말 급수의 동음이의어(there/their)는 소리만으로는 가릴 수 없어 문장 급수에서만 다룹니다.
- **직접 만든 급수표는 브라우저 음성을 씁니다.** 기기에 한국어 목소리가 없으면 소리가 안 납니다
  (설정 화면의 「소리 검사」로 1초 만에 확인됩니다). 그때는 문항마다 녹음해 두면 됩니다.
  내장 급수표는 미리 구운 파일이라 이 문제가 없습니다.
